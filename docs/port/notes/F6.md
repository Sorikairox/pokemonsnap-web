# F6 — 2026-11-14: mouse aim (pointer lock, look, clicks), option 4 "Mouse Aim"

Worked on `web` (from fede807). User request: "Add mouse aim to pokemonsnap". The retrowser host (deployed, ~/Code/retrowser
main, read only) already has the import `rtw_pointer_lock(on)` and the export `rtw_mouse(dx, dy, buttons)`; no host
change was made or needed for the feature to work on a desktop. Design summary: `docs/port/FEATURES.md` ("Mouse aim").

## 1. What the host does (read in ~/Code/retrowser: spec/retrowser.md §4.2 / §4.9, src/host/pages/player.tsx,
src/sandbox/runner.ts, e2e/input.test.ts)

- `rtw_pointer_lock(1)` -> the runner posts `pointer-lock`; the host page sets `wantMouse` and draws
  `[data-field=mouse-catch]` over the picture: "Click to use the mouse (Esc gives it back)". A click on it calls
  `requestPointerLock` (`data-locked` 1). `rtw_pointer_lock(0)` removes it and exits the lock. No manifest key.
- While locked: `mousemove` adds `movementX/Y` (CSS pixels), `mousedown/up` keep a button state (bit 0 left, 1 right,
  2 middle); once per display frame (`requestAnimationFrame`), if the motion is not 0 or the buttons changed, one
  `rtw_mouse(dx, dy, buttons)` (each clamped to +-32767). The runner calls it at once (also while the game is paused).
- The click that captures the mouse happens before the lock: the module never sees it (checked in e2e).
- Esc: the browser exits the lock; `pointerlockchange` sets the buttons to 0 (one `rtw_mouse(0, 0, 0)` follows); the
  prompt stays as long as the module wants the mouse. The host never asks again by itself, and the module does not
  either: after Esc, capturing again is the player's click.
- The overlay is shown whatever the device: on a phone / tablet the prompt also appears over the picture while the
  module wants the mouse (pointer lock does nothing there). See "Host suggestion".
- Context menu: the overlay prevents it, so the right button is free for the game.

## 2. Decisions

- **Option 4 "Mouse Aim"**, bool, default **On** (as asked), `inGame`, kept by the host. Off: the module never asks
  for the mouse and ignores `rtw_mouse`.
- **When the mouse is asked for** (`pc_options.c mouse_lock_update`, every retrace from `port_pad_filter`): on the
  first frame of camera control in a course (`port_snap_course` fresh: handleAnalogStick / updateCameraZoomedIn / the
  tutorial's "Press Z" wait report it, as for F1 / F3), then **kept for the whole course**; given back in the pause
  menu, when the course is over (camera check, menus: no `updatePlayer` for 10 retraces) and when option 4 goes off.
  First version gave it back after 1 s without camera control: in the Beach run that happened at every tutorial
  message and Pokémon scene (65 and 170 retraces), and on the host each would have needed another click. The pause
  menu pauses handleAnalogStick, so "paused" and "in a course" come from a new hook in `updatePlayer` (the player
  object's own update, which runs through the course's scenes and the pause menu): `port_course_frame(IsPaused)`.
  After the pause menu, camera control asks again (the player clicks once).
- **Look**: through F3's path (`port_motion_take`, now summing two `AimSource`s, motion and mouse, each with its own
  log). **0.08 degree a CSS pixel** (82/1024): on a 1024x768 page the picture is ~970 px wide and shows ~70 degrees
  across (fovy 55, 4:3: 2 atan(tan 27.5 x 4/3)), so a move across the picture turns about one field of view (78
  degrees), in the range of desktop shooters' defaults (a few hundredths of a degree per count); zoomed in the fovy is 40, so 3/4 of it (61/1024): the scene moves
  about as far under the mouse in both. The harness shows the mouse path equal to the motion path: 10 x 100 px right +
  10 x 50 px up = `--motion` 8200 / 4100 for 10 retraces (pictures byte-identical), zoomed in 10 x 100 px = 6100.
  No sensitivity setting: the menu has no room for a tenth row and the native letters cannot write digits.
- **Inverted Y**: not applied. "Control Stick Setup: Reverse" is the game's stick preference (`IsAxisYInverted`, read
  only for the stick); mouse up looks up, as motion aim does (F3). Desktop games keep a separate "invert mouse";
  if players ask, a port option could add one.
- **Left click**: zoomed out = F4's Shutter tap through F1's state machine (`snap_mouse` marks the sequence, logged
  "mouse click"); zoomed in (Z, Switch mode, or the right button) = one A press (4 retraces) once
  `port_snap_shoot_ready` has held 3 frames, waiting at most 60 retraces, so a click while the right button's zoom is
  still running is not lost; ignored (logged) while a picture is being taken, while another sequence runs, while
  zooming by Z, outside camera control. The zoomed-in path does not look at `course_ready`: zoomed in it alternates
  within a frame between handleAnalogStick's (0) and updateCameraZoomedIn's (1) report, and the game decides itself
  whether A takes a picture.
- **Right button held**: zoom like Z held (Switch mode: one Z press in, one out), F1's state machine with `snap_rzoom`
  (enter -> aim while held -> leave on release, no A). Already zoomed in by the player: nothing.
- **Middle click**: A while zoomed out, idle and with the zoom available = the game throws an **apple** (A's own job
  zoomed out; `handleItemButtonsPress`). The pester ball stays on B (keyboard). Clean: one 4-retrace A press, nothing
  else changes.
- Clicks outside camera control never reach the game (`port_pad_filter` drops them and logs `[mouse] click ignored`);
  mouse events that arrive while the module does not want the mouse are dropped in `port_mouse_add`.

## 3. Options menu (src/main_menu/A0D4D0.c, A0E190.c)

Row 8 "Mouse Aim  < On > < Off >", built from the native letters like F5's rows. Texts (only letters the native text
has): "Mouse Aim setting." / On "Aim with the mouse. Click to take a / picture, hold the right button to focus." / Off
"Mouse is not used. Aim with the / Control Stick." Nine rows at F5's 16-pixel pitch would put Return at 201 and the box
at 214-247 (off a 240-line screen), so every row, native ones included (labels, values, ":"), is now 15 pixels apart
from y 65 (`PORT_ROW_Y`, `portRowsSpread`): Return stays at 185 and the box at 198-231, as F5 left them. Looked at:
the harness pictures and the e2e's 1024x768 ones (the menu, the row, both values' descriptions).

## 4. Host suggestion (not done: retrowser is read only here; the user deploys)

On touch devices the host shows "Click to use the mouse (Esc gives it back)" over the picture during every course while
Mouse Aim is On (the default). Nothing breaks (the touch controls are above it, the game runs), but the prompt is
noise on a phone. Suggested host change: do not show the mouse-catch prompt when the page uses its touch layout
(`showTouch`) or the device has no fine pointer (`matchMedia('(pointer: fine)')` false), keeping `wantMouse` so a mouse
plugged into a tablet still works. Until then a phone player can set Mouse Aim Off in the game's Options menu. Not
verified in a phone emulation here.
