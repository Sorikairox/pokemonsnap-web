gyro in landscape; (F4) a full-screen landscape touch layout where tapping the top-right corner like a trigger takes

## F3 decisions

- **Where the angles live** (player.c): zoomed out the view is `CurrentDirectionYaw + PlayerViewYaw` and `ViewPitch`
  (updateCameraZoomedOut); zoomed in `PlayerViewYaw` (relative to the cart, [0, 2 pi)) and `ViewPitch`
  (updateCameraZoomedIn). handleAnalogStick runs every frame in both states, before neither matters: the hook adds
  the motion there. Increasing `PlayerViewYaw` turns right in both states (vector (-sin, cos) in a right-handed frame;
  confirmed: zoomed-in motion +20 degrees = stick right for 14 frames, picture identical but for 0.05 degrees).
- **1:1**, integer sums in 1/1024 degree (no drift), converted once per frame.
- **Limits**: pitch clamped to `MinPitch`..`MaxPitch` (-22.5 / +45, `setPitchLimits`), and past a limit the excess
  is lost (mouse-look ratchet; the view moves back at once when the phone tilts back). Yaw has no limit in the game:
  zoomed out the facing changes by a quarter turn past +-0.3 pi (the hook does the same change as
  updateCameraZoomedOut but keeps the excess instead of snapping to -+0.2 pi, so 90 degrees of phone = one facing);
  zoomed in it wraps.
- **Stick + motion** add up. **Control Stick Setup** (inverted Y) is not applied: it is a stick preference; physical
  tilt has one natural direction.
- **When**: taken while handleAnalogStick runs and input is enabled; held while zooming (gDirectionIndex -2) and
  during a zoomed-in C-button turn / the tutorial's zoomed pause (applied afterwards); dropped while input is
  disabled or paused, and by the PC layer when player.c has not taken it for 10 retraces (menus, pause menu, camera
  check, cut-scenes, zoomed-out C-button turns, during which handleAnalogStick is paused). Sums held to +-90 degrees.
- **No port option 3**: the host's toggle (default off, it owns the iOS permission prompt) is the only switch that
  makes sense; a second in-game switch would only add a way for it to silently do nothing. With the toggle off no
  `rtw_motion` call arrives and the game runs exactly as before.
- port/web/index.html: no DeviceMotionEvent; the local page is a scripted harness with no live input (`--motion`
  covers it).

## F4 decisions

- One tap (the press, any length) runs F1's state machine with `snap_shutter` set: idle -> enter (Z held / one Z press
  in Switch mode) -> aim (no hold: waits for `shoot_frames >= 3`) -> shoot (A for 4 retraces, Z kept) -> leave (Z let
  go / one Z press) -> idle. Already zoomed in: aim -> shoot -> idle (no zoom out).
- **Ready = a game state**, not a delay: `updateCameraZoomedIn` reports each zoomed frame whether A takes a picture
  now (no zoomed-in C turn, the game's 10-frame minimum between photos over). Three such frames are required because
  the photo and the Pokémon it scores come from the frame the detector (pokemon_detect.c, a post-process copied to the
  game one frame later) last analysed, which lags the camera: with 3 that frame is a zoomed-in one, not the last step
  of the zoom. Measured: zoom 11 retraces, ready after 2 more, the whole tap ~26 retraces (0.43 s).
- A second tap during a sequence (or while zooming, while Snap is held, outside camera control, while the zoom is not
  available) is **ignored**, with a `[snap] shutter tap ignored at retrace N (reason)` line; queuing would fire a
  picture at a moment the player did not choose. Not tied to option 1 (the Snap button's on/off).

## Interface notes for the host side

- Workable as specified. Two things the host must do for it to reach players: (1) the check tool / host schema must
  accept `controls.motion` and `controls.extra[].place` (today `additionalProperties: false` rejects both; build.sh
  ships without them until `RTW_MJS` knows them, so **rebuild rtw-dist after the host's tool update**), and (2) list
  `rtw_motion` (arity 3) as a standard export (today a warning).
- `rtw_motion` before `rtw_input` in the same display frame: the module only sums, so the order does not matter to it.
- A Shutter tap shorter than one retrace is kept by the module; the host need not stretch it.

## Open

- A real phone: gyro noise / drift at rest (the module applies whatever arrives, 1:1; a dead zone or smoothing, if
  needed, belongs to the host's sensor code), comfort of 1:1 when the cart turns, and the corner zone's reach.
- Zoomed-out C-button turns drop the motion of those ~16 frames (handleAnalogStick is paused by the game); holding it
  instead would apply a jump at the end of the turn. Left as is.
- No numeric read-out of the camera angles (verified by pictures); a debug log of PlayerViewYaw/ViewPitch would need
  floats through game-code varargs.
