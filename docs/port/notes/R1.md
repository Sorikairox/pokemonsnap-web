## Root causes (evidence)

1. **Flat grey cliffs / end tunnel.** Probe at Beach retrace 8001, pixel (200,120): the last triangle there is a cliff
   with a CI4 64x64 rock texture (dumped: high contrast), tile size 512x128, clamp bits, mask 64, s 376..436. The
   bound GL texture had `WRAP_S = 0x812F` (CLAMP_TO_EDGE). The list sets a 64x64 tile size, loads, and draws with
   512x128 over the same TMEM; `tile_texture`'s fast path (same TMEM generation, descriptor, w/h) returned the
   texture created for the clamped size. Fix: wrap modes set at every bind; the cache key no longer has them.
   After: `port_work/r1_fix1/f08001.png`, `f11501.png` (rock texture visible; crop `r1_fix1/crop_l.png`).
2. **Sky box corner rectangles.** Probes at retrace 3801 (10,30), (150,2), (310,100): the background mesh (64x32
   cloud texture, no Z) has vertices at w = 0 exactly with z = -20 (behind the near plane). By hand, the projective
   interpolation at (2..25, 8..120) varies t from 29.5 to 6; the picture showed one colour. GL near-clips such a
   vertex into one with w ~ 10 projected ~50000 px off screen and SwiftShader filled the strips with one texel and one
   shade. F3DEX2_NoN never clips at the near plane; it clips the four side planes (the game sets clip ratio 1). Fix:
   such triangles (any vertex w <= 0 or z < -w) are clipped on the CPU against the colour image's side planes,
   attributes linear in the clip parameter. Counter `clipped` in `[gfxstat]` (~1400 per 150 retraces on Beach).
   After: `port_work/r1_sky2/f03801.png` (clouds to the corners).
3. **Darker left band on Oak's check: intended.** Retrace 14601 list: 450 texture rectangles over x 0..116 (canvas
   0..232), XLU (`IN*A_IN + MEM*1MA`, FORCE_BL), prim colour FFFFFF80, texture 109F2A40. C: photo_check/98C330.c
   creates the sprite `D_801F2AD0_9A2540` ("black square", width 132, height 240, alpha 128) hidden, and
   `func_801DE02C_98DA9C` slides it from x = -211 to x = -12 and holds it. Measured: left pixels are 0.45..0.5 of the
   right ones (`r1_route/f15600.png`: (41,46,99) vs (92,107,200)). No change.
4. **Intro "mist" strip with hard right / bottom edges.** Probes at retrace 209, (293,160) / (297,160): the strip is
   an IA8 bush billboard (texture dumped: alpha 15 except the bottom rows; s = 0 and t = 0 are its right and bottom
   polygon edges), fogged ~45 %, at w ~ 5000 behind a hill at w ~ 1800, drawn over the hill. Its othermode L had
   `G_ZS_PRIM` set, never set in that list: the end of the previous frame's list (0x109252F8, the UI) sets
   `gDPSetDepthSource(G_ZS_PRIM)` and the next frame's render modes only write the upper 29 bits. On the console the
   RSP's DMEM othermode copy is reloaded from the ucode data at every task (offset 0xC8 = `EF080CFF 00000000`, read
   from the ROM's F3DEX2_NoN and L3DEX2 data segments). The same leak affected **every world triangle** (Beach probes
   show L = ...7C / ...4C: primitive depth, i.e. painter's order). Fix: rsp copy of othermode, reloaded at task start
   and `G_LOAD_UCODE`. After: `port_work/r1_om/f00210.png` (the hill hides the bushes, the tree trunk is solid);
   Beach `r1_route2/f06000.png` (cliff continuous, no stacked seam; S6 had one).
5. **Primitive depth units** (found while checking 4): the game sends `gDPSetPrimDepth(sz * 32)` with sz the screen z
   of a vertex (`ndc * vscale[2] + vtrans[2]`, app_render/47380.c and effect.c); the renderer used `z / 32767`, while
   vertices map screen z / 1022. Now `z / 32` goes through the viewport like a vertex.

Not caused by the renderer (checked, no change): `G_BRANCH_Z` LOD choice (thresholds decode to 600 / 4470 units with
near 10 / far 25600; the reference vertex's screen z equals `G_DEPTOZS` exactly).

Not needed by these bugs (not implemented): texture LOD / mipmaps / detail, 3-point filter, dithering, chroma key.
Texture-rectangle batching across loads needs an atlas or array texture: not cheap, not done (rectangles sharing a
load already batch; 7.6 ms per retrace on SwiftShader, unchanged).

## Verified vs assumed

Verified (DL / state analysis and pictures): each root cause above from the probe logs, decoded lists, texture dumps
and the game's C; each fix by a hand-made gfx test that fails without it; pictures before / after looked at (paths
above, all in this worktree's `port_work/`; before: `r1_base/f03801.png`, `f08001.png`, `f11501.png`,
`port_work/r1_mist/f00211.png`). S6 route (HANDOFF S6 command, 16500 retraces): Pidgey **Total 2810** with every
fix (`r1_route3/f15600.png`); two browser runs identical (21/21 PNGs, `[task]` logs, 28 MB journals); node replay of
the regenerated journal (`port-test --readback port_work/r1_route3/readback.bin`, same input): 10223 `[task]` hashes
identical to the browser's. `port/gfx/test/run.sh`: 22/22. Matching build: `build/pokemonsnap.z64: OK`.

Assumed (no emulator reference): that the console draws the sky's eye-plane triangles smoothly (follows from the
microcode's side-plane clipping, not compared with a capture); that `G_RDPSETOTHERMODE` also updates the RSP's copy;
the RSP clipper's attribute interpolation (linear in the clip parameter) and GL's perspective-correct shade instead
of the RDP's screen-linear shade; that nothing else of the RDP / DMEM state leaks across tasks on the console in a
way the port misses (only othermode checked; `rsp_reset` resets the rest each task).

## Remaining

- Near-plane region: what lies between the eye and the near plane is still removed by GL (the console draws it with
  a clamped Z). Not seen on the route.
- Clamp + mask with a tile larger than the mask repeats forever in GL; the RDP clamps at the tile edge.
- Probe not exported to the page; texture-rectangle batching across loads; LOD / 3-point filter / dither / chroma key
  (none needed by the bugs seen).
