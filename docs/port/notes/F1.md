# F1 — 2026-11-09: taking pictures on a touch screen (Snap button, Options row)

Worktree branch from `web` d9423fb. Asked for: a zoom toggle option, a Snap extra button, an inverted-Y option, all
in the game's own Options menu, kept by the host (not in the save). Design and option table: `docs/port/FEATURES.md`.

## Finding: two of the three already exist in the game

The title's Options menu (main_menu A0E190.c, rows 0-4) has **"Z Button Setup: Hold / Switch"** (player flag
`PFID_ZOOM_SWITCH` -> `ZoomSwitchMode`: in Switch mode a Z press zooms in and the next one zooms out, tutorial
included: `func_803552B0_4F56C0` handles both modes) and **"Control Stick Setup: Reverse / Normal"**
(`PFID_INVERTED_Y` -> `IsAxisYInverted`, used only in `handleAnalogStick`, i.e. aiming in a course). A port option
for either would duplicate a setting the player already sees, with two sources of truth; so none was added. These two
are player flags in the save struct: the Options menu sets them in RAM and they reach the flash with the next save
(Oak's lab / gallery), exactly as on the console.

## Traps met

- **Sprite widths must be a power of two**: a 240-pixel-wide text sprite came out smeared on its right side (LoadBlock
  dxt only steps exactly through rows of 2^n 64-bit words); 128 / 256 / 64 are clean.
- **Overlay .bss is laid out at the console's addresses** (vbe.py `bss_layout`): growing `D_800E8378_A0F908[5]` to
  `[6]` would make entry 5 alias `D_800E838C_A0F91C`. The array keeps its size; A0E190.c uses `port_OptLabels[6]`
  through a `#define` under PORT.
- The window font's `'・'` (first table match) is a three-dot glyph: the bullet is drawn as a 2x2 dot instead.

## Verification (pictures looked at; all in `port_work/f1/`, ROM-derived, not committed)

- Options menu (`opt3`, `e2e/15..18-options-*.png`): the new row, its description, editing (Off highlighted, Off
  description), Return -> `[option] 1 = 0 (game menu)`; after a reload the row shows Off.
- Snap, Hold mode (`snap1`, `snap_final`): Beach tutorial, bit 16 held 4000..4120: zoomed in with "Press A to shoot"
  (f04050), on release film 60 -> 59 and zoomed out (f04150); `[snap]` idle->enter 3999, aim 4010, shoot 4119, leave
  4130, idle 4132. Option off (`--option 1=0`, `snap_off`): nothing happens, film stays 60.
- Snap, Switch mode (`snsw`, save with zoomSwitch=1 via `snap_save.py --write --flag zoomSwitch=1`): two Snap presses
  -> two pictures (60 -> 59 -> 58), the camera zooms out after each.
- Zoom toggle (native Switch, `zsw`): Z tapped (3 retraces) at 1700 -> stays zoomed; A at 1800 and 1900 -> 58; Z tapped
  at 2000 -> zoomed out.
- Inverted Y (native "Normal", `inv5`, Tunnel, Z held + stick up): default ("Reverse") looks down at the ground,
  inverted looks up at the sky; menu navigation with the flag set (`inv_menu`) still moves down on stick down.
- Equivalence (`eq.sh`, Beach route with Z held, 6000 retraces, `--audio`): vs the `web` build, PNGs f02000..f06000
  identical, PCM hash identical (958e8e15), `[task]` sequence and command counts identical (hashes hold wasm
  addresses). **Not identical: 32 pixels of the name-entry card (f01000 / f01500, x 325-352, y 227-232 of 640x480)**.
  The `web` build is deterministic there (two runs identical), and commit 1 alone (no main_menu change) shows the same
  kind of difference: a pre-existing layout-sensitive read (some image or texture load reads bytes that depend on where
  the link puts things), not the features. Worth a renderer look (S10a / R-session).
- `port/rtw/build.sh`: `rtw.mjs check --rom` OK with the .z64 and the player's .n64, romscan 0 runs >= 64 bytes.
  `node port/rtw/e2e.mjs`: **e2e: PASS** (desk, touch incl. Snap shown at 160,754 70x32 portrait / 427,354 landscape
  and reaching pad 0, options, wrong, offline). `port/gfx/test/run.sh` CHECKS + CHECKS2 ALL OK; `port-test --frames
  5000` 0 stubs; matching build `build/pokemonsnap.z64: OK`.
